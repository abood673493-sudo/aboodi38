# SSH Manager Panel

لوحة إدارة لحسابات أنفاق SSH على سيرفر Linux تملكه: تسجيل دخول آمن للمدير،
لوحة تحكم بحالة السيرفر وبيانات حقيقية، إنشاء/تعديل/تعطيل/حذف حسابات SSH،
تحديد تاريخ انتهاء، عرض الاتصالات النشطة والاستهلاك الفعلي، وسيط نقل
WebSocket/TLS متوافق مع عملاء مثل HTTP Injector، وإدارة شهادات TLS لنطاق
فرعي.

**Backend:** Go · **Frontend:** React + TypeScript · **قاعدة البيانات:** PostgreSQL

---

## 1. مبادئ التصميم (مهم قبل القراءة)

- **لا بيانات وهمية.** كل رقم تراه في اللوحة (استهلاك، اتصالات نشطة، حالة
  السيرفر) يُقرأ من مصدر حقيقي على النظام (`/proc`, `ps`, systemd
  IPAccounting, قاعدة البيانات). إن لم يتوفر مصدر حقيقي، تُعرض "—" أو "لا
  توجد بيانات"، وليس رقمًا مختلقًا.
- **لا تنفيذ أوامر حرة من الويب.** الـ backend لا يبني أبدًا سطر أوامر (shell
  string) من مدخلات المستخدم. كل عملية تلمس النظام (إنشاء مستخدم، حذفه،
  إصدار شهادة...) تمر عبر ثنائي صغير مخصص (`sshpanel-helper`) ينفّذ مجموعة
  ثابتة ومحدودة من الإجراءات فقط، بعد إعادة التحقق من كل مدخل بنفسه، عبر
  قاعدة `sudo` مقيّدة بهذا الثنائي حصرًا. تفاصيل كاملة في [`docs/SECURITY.md`](docs/SECURITY.md).
- **عملية الـ API نفسها لا تعمل كـ root أبدًا.** تعمل بحساب نظام مقيّد
  (`sshpanel-api`)، وأي صلاحية جذر تمر عبر الثنائي المقيّد أعلاه فقط.

## 2. البنية

```
ssh-manager-panel/
├── backend/            # Go: API + وسيط WebSocket/TLS + الثنائي المقيّد
│   ├── cmd/server/            # العملية الرئيسية (API + الوسيط)
│   ├── cmd/bootstrap-admin/   # أداة سطر أوامر لإنشاء أول مدير فقط
│   ├── cmd/sshpanel-helper/   # الثنائي الوحيد الذي يعمل كـ root
│   ├── internal/              # منطق التطبيق (مقسّم بحزم، كل حزمة لها اختبارات)
│   └── migrations/            # مخطط قاعدة البيانات (SQL صرف)
├── frontend/           # React + TypeScript (Vite)
├── deploy/             # ملفات systemd و nginx و sudoers و sshd وسكربت التثبيت
└── docs/               # تفاصيل الأمان والمعمارية
```

شرح أعمق للمعمارية في [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## 3. المتطلبات

- Ubuntu 22.04 أو 24.04 (سيرفر تملكه فعليًا، بصلاحية root).
- نطاق فرعي (subdomain) تتحكم بسجلات DNS الخاصة به - اللوحة **لا تنشئ أو
  تعدّل سجلات DNS**؛ هذا يتم يدويًا عند مزوّد النطاق قبل إصدار الشهادة.
- اتصال إنترنت طبيعي على السيرفر (لتثبيت الحزم ولتحدي ACME HTTP-01).

## 4. التثبيت على Ubuntu

### الطريقة الموصى بها: السكربت الآلي

```bash
git clone <رابط-مستودعك> ssh-manager-panel
cd ssh-manager-panel
sudo bash deploy/install.sh
```

يقوم السكربت بـ:

1. تثبيت PostgreSQL وnginx وcertbot وGo (إن لم يكن مثبّتًا أو كان قديمًا)
   وNode.js 20.
2. إنشاء حساب النظام المقيّد `sshpanel-api` ومجموعة `sshpanel`.
3. بناء الـ backend والـ frontend.
4. تثبيت `sshpanel-helper` وقاعدة الـ sudoers المقيّدة والـ sshd hardening.
5. إنشاء قاعدة البيانات وتشغيل المخطط.
6. توليد `JWT_SECRET` وكتابة `/etc/sshpanel/sshpanel.env`.
7. تشغيل `bootstrap-admin` تفاعليًا لإنشاء أول مدير (سيُطلب منك اسم مستخدم
   وكلمة مرور تفي بشرط القوة: 12 حرفًا فأكثر، حرف كبير وصغير ورقم ورمز).
8. تفعيل خدمة `sshpanel-api` ومؤقّت تجديد الشهادات.

**راجع السكربت قبل تشغيله** كما تفعل مع أي سكربت يُعدّل حسابات النظام
وsudo والخدمات.

### بعد السكربت: خطوات تحتاج نطاقك الحقيقي (غير مؤتمتة عمدًا)

```bash
# 1) وجّه سجل A/AAAA لنطاقك الفرعي إلى عنوان هذا السيرفر عند مزوّد DNS.

# 2) عدّل deploy/nginx/sshpanel.conf (استبدل ssh.example.com بنطاقك) ثم:
sudo cp deploy/nginx/sshpanel.conf /etc/nginx/sites-available/sshpanel.conf
sudo ln -s /etc/nginx/sites-available/sshpanel.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 3) في /etc/sshpanel/sshpanel.env اضبط:
#    FRONTEND_ORIGIN=https://<نطاقك>
#    BRIDGE_DOMAIN=<نطاقك>

# 4) سجّل الدخول إلى اللوحة (https://<نطاقك>) → صفحة "الشهادات والنطاق"
#    → أصدر شهادة لنطاقك. أو من سطر الأوامر:
sudo -u sshpanel-api sudo -n /usr/local/bin/sshpanel-helper \
  cert-issue <نطاقك> <بريدك> sshpanel-api

# 5) في /etc/sshpanel/sshpanel.env اضبط:
#    BRIDGE_TLS_CERT=/etc/sshpanel/certs/<نطاقك>/fullchain.pem
#    BRIDGE_TLS_KEY=/etc/sshpanel/certs/<نطاقك>/privkey.pem
sudo systemctl restart sshpanel-api
```

من هذه اللحظة، وسيط WebSocket/TLS (المنفذ 8443 افتراضيًا) يستقبل اتصالات
عملاء مثل HTTP Injector على `wss://<نطاقك>:8443/` ويمررها مباشرة إلى sshd
المحلي - المصادقة تتم بواسطة sshd نفسه باسم مستخدم وكلمة مرور حساب SSH الذي
أنشأته من اللوحة.

### تفعيل SSH hardening (اختياري لكنه موصى به)

السكربت يثبّت `/etc/ssh/sshd_config.d/99-sshpanel.conf` تلقائيًا، والذي
يقيّد حسابات مجموعة `sshpanel` على الأنفاق فقط (بدون shell تفاعلي)، فوق
القيد الأساسي (`--shell /usr/sbin/nologin`) الذي يضعه `sshpanel-helper` عند
إنشاء كل حساب.

### التثبيت اليدوي

إن فضّلت كل خطوة بنفسك بدل السكربت، راجع محتوى `deploy/install.sh` نفسه -
كل خطوة فيه معلّقة ومستقلة ويمكن تنفيذها يدويًا بنفس الترتيب.

## 5. التطوير المحلي

### Backend

```bash
cd backend
cp .env.example .env   # عدّل DATABASE_URL وJWT_SECRET محليًا
go run ./cmd/server
```

### Frontend

```bash
cd frontend
npm install
npm run dev   # يفتح على http://localhost:5173 ويمرر /api إلى :8080
```

## 6. الاختبارات

### Backend (تعمل بالكامل محليًا، بدون أي اعتماد على سيرفر خارجي)

```bash
cd backend
go vet ./...
go test ./...
```

تغطي الاختبارات: تسجيل الدخول والقفل بعد محاولات فاشلة، صحة الـ JWT، التحقق
من أسماء المستخدمين والنطاقات، منطق إنشاء/تعديل/تعطيل/حذف الحسابات (بما في
ذلك التراجع عن سجل قاعدة البيانات إذا فشل إنشاء مستخدم النظام الحقيقي)،
صلاحيات الأدوار (RBAC) والمصادقة، تحليل جلسات SSH النشطة، وتفويض عمليات
الشهادات.

**تم أيضًا التحقق يدويًا بالكامل** (ليس فقط بالاختبارات الآلية) أثناء بناء
هذا المشروع: تشغيل فعلي ضد PostgreSQL حقيقي، وتسجيل دخول حقيقي عبر HTTP،
وإنشاء/تعطيل/حذف **مستخدم Linux حقيقي** عبر الثنائي المقيّد، والتأكد من أن
حساب الخدمة غير المميز يستطيع فقط تنفيذ هذا الثنائي عبر sudo ولا شيء آخر.

### Frontend

```bash
cd frontend
npm install
npm test
```

> **ملاحظة شفافية:** بيئة التطوير التي بُني بها هذا المشروع لا تملك وصولًا
> لسجل npm (شبكة مقيدة)، لذلك لم يُشغَّل `npm install`/`npm test` فعليًا
> هناك - الكود روجع يدويًا بعناية (توافق الأنواع، الاستيرادات، منطق كل
> اختبار). شغّل الأوامر أعلاه على جهازك/سيرفرك للتأكد، وأبلغ لو ظهر أي خطأ.
> الـ backend بالمقابل بُني واختُبر وشُغّل فعليًا بالكامل في تلك البيئة.

## 7. الأدوار والصلاحيات

| الدور | القراءة | إنشاء/تعديل/تعطيل حساب | حذف حساب | الشهادات |
|---|---|---|---|---|
| `viewer` | ✅ | ❌ | ❌ | عرض فقط |
| `operator` | ✅ | ✅ | ❌ | عرض فقط |
| `admin` | ✅ | ✅ | ✅ | ✅ |

إنشاء مديرين جدد يتم **فقط** عبر `bootstrap-admin` من سطر الأوامر على
السيرفر نفسه - لا توجد واجهة ويب لذلك عمدًا.

---

## 8. خارج نطاق هذا المشروع (شفافية)

- **لا تكامل مع مزوّد DNS.** توجيه النطاق الفرعي يتم يدويًا من طرفك؛ لم
  يُحدَّد مزوّد بعينه (Cloudflare/Route53/...) فيُدمج معه.
- **لا مصادقة ثنائية (2FA)** للوحة حاليًا - القفل التلقائي بعد محاولات فاشلة
  متتالية مطبّق، لكن TOTP غير مُنفَّذ. يمكن إضافته لاحقًا دون تغيير جوهري.
- **لا بريد إلكتروني** لتنبيهات انتهاء الحساب/الشهادة - البيانات متاحة عبر
  الـ API لمن يريد بناء تنبيه خارجي عليها.
